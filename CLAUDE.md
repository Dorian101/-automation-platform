# CLAUDE.md

Правила работы над Automation Platform. Единственный источник правил и порядка
релиза. Факты о проекте живут в `docs/`, здесь на них только ссылки. Репозиторий
публичный: никаких адресов, паролей и токенов в этом файле.

| Что нужно | Где |
|---|---|
| Текущее состояние и версия | `docs/PROJECT_STATE.md` |
| Решения и их причины | `docs/DECISIONS.md` |
| Архитектура, плагины, маршруты, инварианты | `docs/AI_CONTEXT.md` |
| Сервер и схема деплоя | `docs/DEPLOYMENT.md` |

Эти файлы большие, целиком их не читать. Перед задачей посмотреть версию и нужный
раздел `PROJECT_STATE.md` и `AI_CONTEXT.md`, а `DECISIONS.md` искать по теме: решение
могло быть принято осознанно. История чатов не источник истины.

## Язык и общение

- С владельцем — на русском.
- Код, комментарии, коммиты и `docs/` — на английском. Тексты страниц вроде
  `/about` и `/project` могут быть на русском.
- Кратко, как коллега: сначала суть, да/нет — прямо, без вежливых оборотов и
  пересказа своих действий. Таблицы и короткие списки вместо абзацев.
- Если просьба владельца только навредит работе, предупредить до начала, а
  решение оставить ему.

## Разработка

- Непонятна задача или есть несколько трактовок — спросить, не выбирать молча.
- Есть подход проще — сказать об этом.
- Никаких функций, абстракций и настроек сверх запрошенного. Не писать тесты для
  невозможных сценариев. Если 200 строк можно заменить 50 — переписать.
- Каждая изменённая строка должна вести к запросу. Не улучшать соседний код, не
  рефакторить то, что не сломано, и держаться существующего стиля.
- Сирот от своих правок удалять. Чужой мёртвый код — упомянуть, но не трогать.
- Критерий успеха задаётся заранее и проверяется: не «добавить валидацию», а
  «тесты на неверный ввод написаны и проходят».
- Новый файл можно создать, если он нужен задаче: назвать его в отчёте. Новую
  зависимость и архитектурное решение — согласовать заранее.
- Новая функция — плагин. Бизнес-логика не зависит от транспорта, ядро не знает
  о внутренностях плагинов, ошибки обрабатываются в Dispatcher.
- Завершать по одному спринту. Локальные правки делать без пауз на каждый шаг;
  останавливаться перед тем, что трудно откатить.
- `frontend-design` подключать только по решению владельца: он склоняет
  переделывать внешний вид, а эти правила требуют обратного.

## Локальный стенд

```bash
uv run ruff check .
uv run pytest
# Обязательно перед запуском. Лежит рядом с основной копией, команда работает и из worktree.
"$(git rev-parse --path-format=absolute --git-common-dir)/../../automation-platform.agent/check-local-bot.sh"
uv run python -m app.main  # бот и веб на 127.0.0.1:8080
```

- Скрипт проверяет, что в локальном `.env` не продовый токен бота. Два поллера на
  одном токене отключают продового бота.
- Без доступа к `api.telegram.org` падает весь процесс вместе с вебом.
- При `prefers-reduced-motion` CSS-анимации гаснут, а SMIL и `about_hero.js`
  проигрываются. Этот флаг бывает включён на рабочих ноутбуках политикой.
- В worktree нет игнорируемых файлов: `.env` остаётся в основной копии, поэтому стенд
  запускается оттуда. Тестам `.env` не нужен.
- `stand` в `.claude/launch.json` подключается к уже запущенному стенду и сам его не
  поднимает, чтобы не обойти проверку токена. Он показывает код основной копии.

## Релиз

**Прод не трогать без явной команды владельца. Каждый пуш в `main` перезапускает
сервер**, если в GitHub Actions прошли `ruff` и `pytest`. Эта проверка не заменяет
шаг 3: провал в CI значит, что код уже в `main`, а на сервере нет. Несвязанные
правки лучше собирать в один пуш.

1. **Ревью.** `/code-review` по полному диффу, если правка больше ~100 строк или
   меняет публичный контракт: команду, маршрут, интерфейс плагина, схему, ключ
   конфигурации.
2. **Безопасность.** Глубина зависит от правки:
   - зависимости изменились — `uvx pip-audit --path .venv`;
   - новый вход, публичный адрес, запись, авторизация, куки, заголовки — пройти
     по OWASP: инъекции, доступ, XSS, CSRF, секреты в логах и репозитории;
   - лимитеры, `compare_digest`, флаги кук, nonce — проговорить крайний случай и
     проверить, что он закрыт.

   Реальная находка чинится в этом же спринте, теоретическая записывается в
   `docs/DECISIONS.md`.
3. **Проверки.** `uv run ruff check .` и полный `uv run pytest` оба чистые.
4. **Версия.** Поднять в `docs/PROJECT_STATE.md`, раздел `Current version`, в каждом
   релизе, даже если правка только в доках.
5. **Доки.** Всегда `PROJECT_STATE.md` и `AI_CONTEXT.md`; `DECISIONS.md` и
   `DEPLOYMENT.md`, если есть решение или изменился деплой.
6. **Коммит.** Короткая императивная строка и тело про то, зачем. Затем прочитать
   `git show --stat HEAD`: список файлов должен быть ожидаемым.
7. **Тег.** Лёгкий `git tag v0.X.Y` на коммите с новой версией.
   `git rev-parse --short HEAD` и `git rev-parse --short v0.X.Y` должны совпасть.
   Опубликованный тег не двигать, задним числом теги не ставить.
8. **Пуш.** Ветка и тег вместе. Из worktree: `git push origin HEAD:main` и
   `git push origin v0.X.Y`.
9. **Проверка деплоя.** Зелёный пуш не доказательство:
   - коммит на сервере равен локальному `HEAD`;
   - `systemctl is-active automation-platform` отвечает `active`;
   - затронутая страница открывается на домене, в консоли нет ошибок.

   Доступ у read-only пользователя `observer`, он не видит `.env` на сервере. Адрес
   и ключ — вне репозитория.

Шаг пропущен — назвать его и причину.

## Ловушки

- `git checkout <файл>` молча выбрасывает незакоммиченную работу.
- Версию легко забыть при теге. Тег не двигать, чинить следующим коммитом.
- Тестовые env в `tests/conftest.py` стоят выше импортов намеренно: в фикстуре
  тесты пойдут против development-базы и опустошат её.
- `load_dotenv()` вызывается внутри `app/core/config.py`: `Config` читает
  окружение при импорте.
- `_clean_db` дропает все таблицы, а не список.
- Публичный путь и индексируемый — разное: страницу для поисковиков добавить в
  `INDEXABLE_PATHS`, иначе краулер о ней не узнает, а тесты останутся зелёными.
- Файлы миграций после деплоя не менять.
- `/health` не за сессией, но за транспортным секретом `X-Platform-Auth`.
- У `automation` на сервере `nologin`: `sudo -u`, а не `su`.
